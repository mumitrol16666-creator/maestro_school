## Задача экрана

Главная отвечает на один вопрос: «Что ученику делать сейчас?»

Курсы остаются в системе, но больше не занимают главный hero-блок и не
повторяются несколько раз.

## Иерархия

1. Header: бренд, уведомления, профиль.
2. Приветствие.
3. Компактные реальные показатели: Points, Coins, достижения.
4. «Сейчас»: единственное наиболее важное действие.
5. Цель текущего месяца и progress Monthly Plan.
6. Три первые задачи из Unified Tasks.
7. Дополнительный самостоятельный курс.
8. Нижняя навигация.

## Правило hero «Сейчас»

Hero показывает только один объект с максимальным приоритетом:

1. живой урок начинается в ближайшие 60 минут;
2. задание возвращено на доработку;
3. задание с точным просроченным сроком;
4. задание с ближайшим точным сроком;
5. текущий пункт месячного плана;
6. следующее курсовое действие.

Один объект нельзя одновременно повторять в hero и в первых трёх задачах.

## Подписи источников

Короткие технические badges `В школе / Онлайн / Курс` не используются как
единственное объяснение. Ученик видит человеческий контекст:

- «Урок в школе»;
- «Онлайн с преподавателем»;
- «Самостоятельный курс».

Источник выводится вторичной строкой под названием задания. Главное место в
карточке занимает само действие, а не архитектура системы.

## Тексты главного действия

Generic CTA «Продолжить» запрещён, кроме явно подписанной карточки курса.

| Объект | CTA |
|---|---|
| Офлайн-ДЗ | Открыть ДЗ |
| Онлайн-ДЗ без сдачи | Сдать задание |
| Онлайн-ДЗ после возврата | Доработать |
| Курсовое обычное ДЗ | Открыть урок |
| Курсовой тест | Пройти тест |
| Онлайн-урок начинается | Войти в урок |
| Ближайший урок в школе | Детали урока |
| Пункт месячного плана | Открыть план |
| Явная карточка курса | Продолжить курс |

## Адаптивность по типу обучения

Главная не имеет одного фиксированного набора рекламных блоков. Она собирается
из реальных данных ученика.

### Только офлайн-школа

- hero: ближайший урок в школе или самое срочное ДЗ преподавателя;
- Monthly Plan: основной учебный progress;
- Tasks: только реальные задания после уроков;
- дополнительный курс скрыт;
- онлайн-блок скрыт;
- освободившееся место занимает ближайшее расписание;
- никаких пустых заглушек «Курс не назначен» и «Онлайн-заданий нет».

### Офлайн плюс самостоятельный курс

- hero выбирается по общему priority engine;
- Monthly Plan остаётся выше курса;
- курс показывается одним вторичным компактным блоком;
- задачи курса входят в Unified Tasks.

### Только самостоятельный курс

- hero: следующее действие курса или возвращённое ДЗ;
- Monthly Plan скрыт, если преподаватель его не публиковал;
- блок расписания школы скрыт;
- основной course progress допускается, но не повторяется второй карточкой.

### Офлайн плюс онлайн с преподавателем

- ближайший живой урок выбирается по времени независимо от формата;
- задания обоих форматов находятся в одной очереди;
- source указывается человеческой строкой;
- пустой самостоятельный курс не показывается.

Нижняя навигация остаётся стабильной во всех вариантах, чтобы пункты не
перепрыгивали после изменения данных.

## Данные блоков

### Метрики

- Points — существующий ledger;
- Coins — существующий coin balance;
- достижения — существующий achievements API;
- level и streak не показываются до реализации настоящей модели.

### Цель месяца

- используется только опубликованный Monthly Plan snapshot;
- progress считается по опубликованным пунктам;
- при отсутствии плана блок скрывается без большой пустой карточки.

### Задания

- используются Unified Tasks;
- показываются только первые три после исключения hero-объекта;
- основной порядок задаёт backend;
- CTA «Все задания» открывает `/tasks`.

### Дополнительный курс

- блок визуально вторичный;
- показывает текущий самостоятельный курс и честный course progress;
- не повторяет следующий lesson отдельными карточками.

## Нижняя навигация V2

- Главная;
- Задания;
- План;
- Школа;
- Профиль.

До реализации маршрута Monthly Plan пункт «План» нельзя выпускать как пустую
кнопку.

## Визуальные правила

- фон почти чёрный;
- тёплое золото используется для CTA и активных состояний;
- красно-оранжевый только для реальной доработки/ошибки;
- карточки имеют одну визуальную иерархию, а не одинаковый вес;
- никаких огромных декоративных изображений;
- source/status распознаются не только цветом, но и текстом/иконкой;
- минимум 44 px для интерактивных зон;
- мобильный экран не имеет горизонтального scroll;
- длинные ФИО и названия проверяются отдельно.

## Что требуется согласовать перед кодом

1. Оставляем ли три метрики в самом верху или переносим их ниже?
2. Достаточно ли в hero преподавателя и времени или обязательно нужен кабинет?
3. Должен ли Monthly Plan занимать второй по размеру блок?
4. Нужен ли отдельный пункт «План» в нижней навигации?
5. Подходит ли плотность: три задачи без раскрытия полного текста?

После согласования макет превращается в component specification с точными
breakpoints, состояниями, props и API mappings. Только после этого меняется код
главной страницы.
