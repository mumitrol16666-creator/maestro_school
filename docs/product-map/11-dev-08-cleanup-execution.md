# DEV-08 — навигация, compatibility cleanup и финальная миграция

Статус: `DONE LOCALLY / RELEASE GATES PENDING`
Дата: 30 августа 2026 года
Граница: только локальный QA-контур; без commit, push, production deploy и production-данных

## 1. Цель

Закрыть оставшиеся пользовательские дубли после `DEV-00..DEV-07E`, не создавая
вторую бизнес-логику и не ломая старые ссылки. В первом уровне каждой роли
остаётся только утверждённая карта экранов, а прежние URL работают как
совместимые точки входа в новый раздел.

## 2. Зафиксированный объём

### 2.1 Ученик

При `FEATURE_ROLE_NAVIGATION_V2=true` первый уровень содержит ровно пять
разделов:

1. `Главная` — `/dashboard`, включая совместимые `/league` и `/board`.
2. `Обучение` — `/learning`, включая `/tasks`, `/monthly-plan`, `/courses`,
   `/lessons`, `/tests` и `/progress`.
3. `Расписание` — `/school-lessons`, включая `/online-lessons`.
4. `Сообщения` — `/messages`.
5. `Магазин` — `/rewards` как витрина за Coins и ссылка на отдельный
   коммерческий контур `https://shop.maestro.com.kz`.

Профиль открывается только через аватар. В нижней навигации нет отдельных
пунктов «Профиль», «План», «Лига», «Курсы», «Тесты» или «Награды».

Внутри «Обучения» одновременно видны четыре компактных действия: «Сейчас»,
«План», «Задания» и «Ещё». В «Ещё» находятся история, курсы и тесты. Старый URL
не копирует данные и использует тот же API/read-model, что и целевой раздел.

### 2.2 Admin и преподаватель

- admin уже использует пять утверждённых разделов при
  `FEATURE_CURATOR_WORKSPACE_V2=true`;
- преподаватель сохраняет четыре рабочих раздела;
- отдельный аккаунт или навигация куратора не создаются;
- CRM остаётся источником истины для уроков, формата, расписания, направлений,
  состава групп и финансовых данных.

## 4. Реализованный UI

- добавлен рабочий экран `/learning` с текущими темами, сводкой и компактным
  списком заданий;
- старые учебные страницы получают единый четырёхпозиционный context switcher;
- магазин показывает две понятные ветки: обычные товары за тенге и товары или
  возможности за Coins;
- desktop sidebar и mobile bottom navigation используют одну карту активных
  route prefixes;
- badges задания, расписания и сообщений перенесены на родительские разделы;
- проверены ширины 320, 375, 390, 430 и 768 px без горизонтального overflow и
  без обрезания названий вкладок.

## 5. Автоматические критерии

Профильный Playwright-набор `student-navigation-v2.spec.ts` проверяет:

1. ровно пять разделов первого уровня;
2. отсутствие старых самостоятельных пунктов;
3. профиль через avatar menu;
4. правильный active state для всех legacy deep links;
5. внутреннюю навигацию обучения и магазина;
6. внешний URL коммерческой витрины;
7. отсутствие горизонтального переполнения на обязательных ширинах.

Текущий профильный результат: `10/10` (`chromium` + `mobile-chromium`). Полный
интерфейсный набор: `92/92`. Backend: `145/145`; CRM backend: `186/186` и
синтаксическая проверка всех `src/test/scripts`. Web/backend typecheck,
production build и `git diff --check` проходят.

На чистой локальной QA-базе пройдены экономика, недельная лига, ДЗ, награды за
урок, родительская видимость, журнал, membership/API/moderation/retention
диалогов и online lessons. CRM fixture lifecycle прошёл создание, изменение,
перенос, отмену, восстановление, online/offline, изменение состава группы и
разовую замену. После прогона QA-база очищена от временных пользователей.

## 6. Запреты до release gate

- не удалять legacy-таблицы, migration history и rollback-адаптеры;
- не импортировать production-данные в локальный seed автоматически;
- не переключать production feature flags;
- не заменять CRM локальной копией расписания или финансов;
- не добавлять складской резерв для Coin-заявок;
- не считать ссылку на коммерческий магазин интеграцией склада или заказов;
- не выполнять commit/push/deploy без отдельной команды владельца.

## 7. Итог DEV-08

Локальный объём DEV-08 завершён. Навигация сведена к утверждённой карте,
безопасные неиспользуемые компоненты удалены, старые deep links сохранены, а
интеграционный и ролевой регресс пройден на изолированной QA-базе.

До отдельного решения о релизе остаются только production release gates:
object storage, malware scanner, backup/restore rehearsal, controlled legacy
migration, production feature flags и наблюдение rollback window. Они не
выполнялись и не имитировались локальными заглушками.
