# План работ по приложению, 17.10.2026

Основание: [карта «как есть»](./12-as-is-map-2026-10-17.md). Решение Владислава 17.10:
правило «учитель Points не начисляет и не снимает, только бонус 1–10 XP» остаётся.
Порядок этапов: **0 → 1 → 3 → 2 → 4**. Причина: этап 0 чинит цифры, которые потом показывают
все три роли; учитель (1) порождает данные для ученика и родителя; родитель (3) — почти
только backend read-model; ученик (2) объёмнее; курсы для внешних (4) — новый продукт
с нерешёнными вопросами и контентом.

«Сделано» для каждого этапа — критерий в конце раздела, проверенный на QA-стеке с
включёнными флагами, DB-тестами и e2e, затем на проде.

## Этап 1. Учитель

Цель: вся работа с учеником — из начатого урока, без выхода с экрана.

### 1.0 Сектор вместо плана месяца (решение Владислава 17.10)

Сектор = ступень программы из плана 14.10, одна сущность вместо «план месяца».

| Сейчас (`LearningPlan`) | Станет (`LearningSector`) |
|---|---|
| уникален по владелец + направление + **месяц** | уникален по владелец + направление + **порядковый номер** |
| темы — свободный текст учителя | темы из **шаблона сектора** (`SectorTemplate` = карточка ступени: мелодия / аккорды / теория / песни / материалы) + правки и добавления учителя |
| перенос незавершённых тем в следующий месяц (`carryover`) | не нужен: сектор открыт, пока не закрыт; следующий сектор открывается только после закрытия текущего, у ученика по направлению ровно один активный сектор |
| закрывается, когда все активные темы 100 % | закрывается, когда все темы 100 % **и сдан тест сектора** (если в шаблоне есть) |
| тема 100 % → 100 Points, план закрыт → 250 | без изменений: тема → 100, сектор закрыт → 250 |
| «план месяца, %» у ученика и родителя | «сектор N из 30, %» |

- Тест сектора: `SectorTemplate.preparedTestId` (из 25 готовых или свой); незакрытый тест выводится на главную ученика как действие «сдай тест сегодня, +20 XP» (в приоритете hero после ДЗ); дневной лимит тестов остаётся.
- Предложения ученика: `SectorProposal` (ученик, направление, текст, ссылка, тип тема/песня/цель, статус new/accepted/declined, ответ учителя). Подаются из `/learning` и карточки сектора; учитель видит в карточке ученика (1.1) и счётчиком в «Сегодня», принимает в текущий или следующий сектор.
- Миграция: существующие `LearningPlan` v2 (сентябрь, октябрь) становятся секторами 1, 2 по порядку месяцев; темы, проценты, история и награды сохраняются; `carryover` и месячные маршруты удаляются.
- Что ещё задевает: месячный отчёт в `/school-lessons` (legacy-план) уходит; «план месяца» у родителя → «текущий сектор»; редакторы плана ученика/группы переписываются под шаблон; `teacher-students.service.ts` считает `planCompletionRate` по текущему сектору.
- Шаблоны секторов — JSON из 30 карточек ступеней после собрания преподавателей (план 14.10); до него сектор можно заполнять вручную, шаблон необязателен.
