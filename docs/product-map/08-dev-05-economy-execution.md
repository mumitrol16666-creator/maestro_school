# DEV-05: новая экономика Maestro

Статус: `DEV-05A..DEV-05E DONE LOCALLY / DEV-07A..DEV-07D DONE / READY FOR DEV-07E`
Назначение: исполняемая техническая карта Points, LEVEL, недельного XP, Coins, серии и достижений
Основание: [01](./01-product-constitution.md), [03](./03-process-event-map.md), [04](./04-technical-change-map.md), [05](./05-development-prompt.md), [07](./07-local-e2e-acceptance-prompt.md)

## 1. Граница DEV-05A

`DEV-05A` создаёт новую экономическую эпоху и безопасный механизм её открытия. Пакет не включает пользовательский LEVEL-интерфейс, финализацию недель, новые призы лиги, серию, медали или магазин наград.

Подтверждённая стартовая формула для каждого активного ученика:

- `0 Points`;
- `LEVEL 1`;
- `0` недельного XP;
- `200 Coins`.

Старые Points, XP, Coins, ранги и достижения не удаляются. Они остаются legacy-историей и не входят в текущий баланс новой эпохи.

## 2. Реализованная модель

- `EconomicEpoch` хранит код, дату начала, статус и стартовую формулу;
- частичный unique-индекс разрешает не более одной активной эпохи;
- `EconomicEpochParticipant` создаётся один раз на активного ученика и хранит исходные legacy-снимки;
- Points, XP, недельные снимки, Coin-баланс и Coin-транзакции получают nullable-ссылку на эпоху; старые строки остаются с `NULL`;
- стартовые 200 Coins создаются отдельной системной транзакцией `economic_epoch` без ложного автора;
- системные V2 Points и attendance XP после cutover требуют активную эпоху и записывают её ID;
- прямые legacy Points за урок и ручные Points после cutover блокируются;
- новая Coin-транзакция после cutover не выполняется, если баланс ученика не открыт в активной эпохе.

## 3. Алгоритм cutover

1. Dry-run читает активных учеников с ролью `student`, `isActive=true`, `deletedAt=NULL`.
2. Для каждого вычисляются legacy Points, XP недели cutover и текущий Coin-баланс.
3. Dry-run показывает количество учеников, старые суммы, новые стартовые суммы и блокеры без записи.
4. Apply получает advisory lock и запрещает параллельное открытие второй эпохи.
5. В одной транзакции создаются эпоха, участники, стартовые Coin-транзакции, новые балансы и audit-запись.
6. Повтор apply возвращает `idempotent=true`, не добавляет новых учеников и не сбрасывает изменившийся после старта баланс обратно к 200.
7. Неактивные и архивные ученики не включаются.

## 4. Локальные команды

```bash
docker compose -f docker-compose.local.yml exec -T backend \
  npm run economy:v2:cutover:dry-run

docker compose -f docker-compose.local.yml exec -T backend \
  npm run economy:v2:cutover:apply

docker compose -f docker-compose.local.yml exec -T backend \
  npm run e2e:economy-v2-cutover
```

Apply в текущем пакете разрешён только при `MAESTRO_QA_LOCAL=true` и локальном `DATABASE_URL`. Production apply, commit, push и deploy не разрешены.

## 5. Критерии приёмки DEV-05A

1. Dry-run не создаёт эпоху, участников или Coin-транзакции.
2. Первый apply включает всех и только активных учеников.
3. Legacy ledger остаётся неизменным и имеет `economic_epoch_id=NULL`.
4. Участник получает старт `0 / LEVEL 1 / 0 / 200` и legacy-снимки.
5. Стартовая Coin-транзакция создаётся ровно один раз на ученика.
6. Повтор apply не меняет Coin-баланс, уже изменённый после открытия эпохи.
7. Другая активная эпоха и несовпадающая конфигурация блокируют apply.
8. Включённый V2 reward-контур не создаёт Points или XP вне активной эпохи.
9. QA E2E удаляет только собственную тестовую эпоху и восстанавливает исходные балансы.
10. Все feature flags по умолчанию остаются `false`.

## 7. Фактический результат DEV-05B

На 28 августа 2026 года локально реализованы:

- единый server-side Points read-model: до cutover читает только legacy ledger, после cutover требует активную эпоху и считает `openingPoints + ledger текущей эпохи`;
- утверждённые границы `LEVEL 1-10`, прогресс внутри текущего диапазона, продолжение Points после `LEVEL 10`, десять цветовых тонов и десять форм эмблем;
- один переиспользуемый `LevelBadge` и `LevelSummary` в профиле, прогрессе и магазине наград;
- старый именованный ранг остаётся только fallback до cutover; при активном V2 он не показывается;
- отдельный `/students/me/points-leaderboard`, top-10 и позиция ученика без внутренних user ID;
- равные Points получают одинаковую competition-позицию (`1, 1, 3`), а полностью равное стартовое состояние не объявляет отдельного лидера;
- top Points визуально и по API отделён от недельного XP, не содержит недельных призов и Coins;
- локальный fixture и compose override заблокированы вне `MAESTRO_QA_LOCAL=true` и локального `DATABASE_URL`.

Проверено: backend typecheck/build, `136` backend-тестов, web typecheck/build и Playwright `3/3` на desktop и `390 px`; горизонтального переполнения на экранах LEVEL и top Points нет. После проверки fixture удаляется, QA seed восстанавливается, а итоговый локальный запуск возвращается к flags `false`.

## 8. Фактический результат DEV-05C

На 29 августа 2026 года локально реализованы:

- четыре разрешённых XP-источника новой экономической эпохи: подтверждённое посещение, принятое учебное ДЗ, подготовленный тест и ручной бонус преподавателя;
- общий лимит посещений: первые два подтверждённых офлайн- или онлайн-занятия недели по `20 XP`;
- лимит ДЗ: первые три принятые работы недели на направление, `15 XP` с первой попытки и `10 XP` после доработки;
- лимит тестов: первые два подготовленных теста недели, `20 XP` с первой попытки и `10 XP` при повторной попытке;
- ручной бонус преподавателя от `1` до `10 XP` суммарно за неделю;
- server-side receipts, epoch isolation, advisory locks и стабильные source keys; legacy-события и общий обходной метод не попадают в V2-рейтинг;
- фазы `live`, `finalizing`, `finalized` в `Asia/Aqtobe`; финализация выполняется не раньше понедельника 12:00;
- неизменяемые `WeeklyLeagueSnapshot` и `WeeklyLeagueSnapshotEntry`, которые хранят место, XP, число событий и расшифровку источников;
- позднее событие после финализации остаётся в журнале, но не меняет сохранённый результат недели;
- отдельные top XP и top Points: недельная активность не смешивается с постоянными Points/LEVEL;
- экран лиги для desktop и телефона без обещаний Coins, серии или достижений из будущего пакета.

Миграция `20260829213000_weekly_league_v2_snapshots` применена только к локальной PostgreSQL. `e2e:weekly-league-v2` проверил смешанный лимит офлайн/онлайн-посещений, оба варианта ДЗ и теста, бонус преподавателя, запрет legacy `monthly_plan +3`, реальное принятие школьного ДЗ, идемпотентную финализацию, позднее событие и отсутствие Coin-транзакций. Проверено: backend и web build, `137/137` backend-тестов, Playwright `6/6` в общем desktop-наборе DEV-05B/05C и `3/3` DEV-05C на мобильном viewport.
