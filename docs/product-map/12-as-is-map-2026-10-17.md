Статус: фактический разбор по коду, не план. Основание: `origin/main` платформы `e2a4322`
и `maestro/main` CRM `ab04e06`. Обе версии подтверждены как прод через `/health`.
Пути: `P/` = этот репозиторий, `C/` = репозиторий CRM. Документы 01–11 описывают

## 1. Два контура и граница денег

```
CRM (деньги, люди, расписание)            Платформа (учёба, экономика наград)
───────────────────────────────           ─────────────────────────────────────
Student / Teacher / Group / Direction ──► User(crmStudentId/crmTeacherId), Direction-проекция
Class (урок) + ClassAttendee ─────────►  OfflineLessonProjection, OfflineLessonStudentCheck
Membership / Payment / accountBalance ─►  только live-чтение, не хранится
Salary / deductions / approve ────────►  запрещено на платформе (всегда 409)
ShopProduct / ShopOrder ◄─────────────    Coins: баланс и леджер на платформе
                                          LearningPlan/Topic/Homework v2, Points, XP, Coins, лига
```

Источник истины по объектам (`P/backend/src/infrastructure/crm/crm-client.ts`,
`C/backend/src/routes/integration.js`):

| Объект | Живёт | Синхронизация |
|---|---|---|
| Ученик, преподаватель | CRM | provision → `User`; пароль CRM→платформа, обратно нет |
| Родитель | **только платформа** (`ParentStudentLink`) | CRM хранит лишь `Enrollment.parentUserId` |
| Группа, расписание | CRM | live GET + проекция урока |
| Посещаемость | CRM | outbox `teacher_attendance`, конфликты в `CrmSyncConflict` |
| Тема урока (текст), ДЗ-текст | CRM `Class.topic/homeworkDraft` | outbox `teacher_submit` |
| План, темы, %, ДЗ v2, попытки, проверки | платформа | в CRM не уходят |
| Абонемент, баланс, оплаты, зарплата | CRM | платформа читает сводку, не хранит |
| Points, XP, Coins, лига, серия | платформа | CRM списывает Coins за товары (`/shop/coins/*`) |

Деньги на платформе: полей цены/тенге в `schema.prisma` нет. Единственная связь с деньгами —
Coins покрывают 0/50/100 % цены товара в магазине CRM (`coinPaymentPercent`); сам магазин для
ученика на проде заглушка («Временно на обновлении», `POST /rewards/:id/redeem` всегда 403).

Транспорт: один общий `INTEGRATION_SERVICE_SECRET` в обе стороны; заголовок
`X-Integration-System` объявляет сам вызывающий, проверки «только CRM»/«только платформа»
держатся на нём (`P/backend/src/presentation/guards/integration.guards.ts:18-36`,
`C/backend/src/middleware/integrationAuth.js:10-35`).

## 3. Главный процесс: урок → отчёт → CRM → награды

```
teacher: Начать урок ──► CRM teacher-start (напрямую)
teacher: посещаемость ─► outbox teacher_attendance ──► CRM ClassAttendee
teacher: Отправить ────► OfflineLessonReportVersion v<n> (pending_sync)
                          └► outbox teacher_submit ──► CRM Class = pending_admin_review
                                                       └► отчёт = pending_review
admin в CRM UI: approve ─► списание, зарплата, notify('lesson.approved')
   (а) колбэк CRM → /notifications/offline-lesson-approved   — требует события admin_approve, иначе 409
   (б) опрос каждые 30 с: CRM status completed → отчёт approving → admin_approve(crm_observed)
       └► confirmOfflineLessonApproval → finalizeOfflineLessonApproval:
            темы % → 100 Points за тему / 250 за план; ДЗ v2; 20 XP + 50 Coins за посещение
       └► уведомления ученику и родителю (только если колбэк был поставлен в очередь)
```

Статусы отчёта: `editing → pending_sync → pending_review → approving → confirmed`, плюс
`conflict`, `correcting`. Outbox: `pending / processing / succeeded / failed / conflict / awaiting_crm`.
Ретраи без лимита (5xx, 409, сеть); 4xx → `conflict`, разбирает координатор.
Файлы: `P/backend/src/application/services/{offline-lesson-report,crm-outbox,crm-approval-reconciliation,offline-lesson-finalization}.service.ts`.

Где застревает (по коду):
- колбэк пришёл раньше опроса → 409, в CRM автоповтора нет, уведомления не уйдут;
- approve из CRM UI шлёт колбэк **без `crmStudentIds`** (`C/backend/src/routes/classes.js:2963-2966`) → уведомления «итог урока» не находят получателей;
- возврат преподавателю в CRM → на платформе отчёт остаётся `pending_review`, повторный submit запрещён;
- reopen подтверждённого урока в CRM откатывает деньги, а награды на платформе остаются (`LESSON_FINALIZED_CORRECTION_UNSAFE`);
- CRM недоступна → у преподавателя падает **каждый** запрос (проверка `session-state` на каждый вызов, `account-session.service.ts:45-55`); семейный кабинет падает целиком.

## 4. Формулы (V2, как на проде)

Файлы: `P/backend/src/domain/product-economy-v2.ts`, `application/services/weekly-league-policy.ts`,
`points.service.ts`, `weekly-league.service.ts`, `learning-plan-v2.service.ts`.

**Points (постоянные, не сгорают):** баланс = `max(0, 0 + Σ points_transactions активной эпохи)`.
Источники только два: тема плана достигла 100 % в проведённом уроке → **+100**
(`learning-topic-mastery:{topic}:{student}`); все активные темы опубликованной версии плана = 100 % → **+250**.
За посещение, ДЗ, тест, урок курса Points **не дают**. Списания и коррекции нет ни у кого.

**LEVEL:** пороги 0 / 300 / 800 / 1500 / 2500 / 3800 / 5400 / 7300 / 9500 / 12000;
`progress = round((points − min) / (next − min) · 100)`. Имена только «LEVEL N».
Старые ранги («Первые струны»…«Маэстро») API возвращает всегда, UI прячет.

**Недельный XP (пн 00:00 – вс, Asia/Aqtobe; финализация пн 12:00, job раз в час):**

| Источник | XP | Лимит/нед. |
|---|---|---|
| подтверждённое посещение (офлайн или онлайн) | 20 | 2 |
| принятое ДЗ (v2 / курс / онлайн) | 15 первая попытка, 10 после доработки | 3 на направление; без `directionId` — 0 |
| подготовленный тест (≥ 70 %) | 20 первая, 10 повтор | 2; каждый тест один раз навсегда |
| бонус преподавателя | 1–10 | 10 на пару преподаватель–ученик |

Место: XP desc → число событий → кто раньше → имя. Цель недели 80 XP.

**Coins:** старт эпохи 200; посещение 1-е и 2-е в неделю по 50; цель 80 XP → 25;
места 1/2/3 → 150/100/50 (при XP > 0); рубежи серии 4/8/12/24/52 недели → 50/100/150/250/500;
завершение курса → `Course.completionCoinsReward`. Траты: только магазин CRM (на проде закрыт).

**Серия недель:** продлевает посещение или принятое ДЗ; тест и бонус не продлевают; защита
CRM (каникулы, пауза абонемента, отмена всех уроков) или куратор (болезнь, семья, другое, ≤ 7 дней).

**Прогресс:** тема 0–100 %, учитель вне урока ≤ 99 %, 100 % только в уроке; статус темы
из процента (0 planned, 100 completed, иначе in_progress). План: `round(completed/active · 100)`,
тема на 60 % даёт 0. Курс: `round(completed/published · 100)` — числитель не фильтрует
удалённые уроки, возможно > 100 % и ложное завершение.

**Тесты:** 25 шаблонов в `domain/prepared-tests.ts` (теория только к 5 первым); строго по порядку;
1 новый тест в день; 2 попытки в день; `score = round(correct/total·100)`, зачёт ≥ 70.
Привязки к дате, уроку или плану нет — «тесты по расписанию» в коде отсутствуют.

**Достижения:** в V2 `evaluateAchievements` возвращает `[]`; вместо них показываются рубежи серии.
Старый каталог из 14 достижений (first_lesson, points_100 …) живёт только для legacy.

## 5. Дыры по четырём задачам

### 5.1 Преподаватель
1. Нет экрана «ученик перед уроком»: контекст в уроке — только последний урок; динамика, сигналы, план, задания — в «Мои ученики» и на трёх отдельных страницах; из урока ссылок туда нет.
2. Страница урока 4086 строк: ~15 блоков, 5 модалок, legacy-поля (баллы 0–100, legacy-план) рендерятся рядом с V2.
3. Изменения тем из урока уходят на сервер только при отправке отчёта (`saveStudentChecks` в `confirmSubmit`); до этого всё в черновике.
4. Баллы: в V2 преподаватель **не начисляет и не снимает Points** (так и утверждено ECON-005/006/076). Единственный ручной инструмент — бонус 1–10 XP, и он доступен только из «Мои ученики», не из урока. Легаси-поле «учебные баллы 0–100» в уроке отправляется как 0.
5. Тема — свободный текст, справочника тем нет; «предложения для плана» = перенос незавершённых тем + чипы из прошлых уроков + захардкоженные пресеты под гитару/вокал. Программы (ступеней) как объекта нет — см. план 14.10.
6. Быстрая тема V2 копирует последнюю версию плана (возможно черновик) и сразу публикует без проверки версии (`learning-lesson-v2.service.ts:834-913`); без направления берёт первое по `createdAt`.
7. Мастерство групповой темы без снимка отчёта начисляет 100/250 Points всему текущему составу группы, включая отсутствовавших (`learning-plan-v2.service.ts:1349-1366`).
8. Учитель видит прогресс черновой версии плана, ученик и родитель — опубликованной; цифры расходятся.
9. Модал «Начать урок» нельзя закрыть; окно «отчёт не раньше чем за 20 минут до конца» только на клиенте.
10. Пробный урок: признак trial считается по-разному в финализации и в уроке v2; онлайн-пробные не фильтруются.
11. Мёртвое: право `coins.award`, `teacherOfflineApi.finish`, `fetchTeacherSalarySummary`, кнопка «Взять заявку» в онлайн-уроках недостижима.

### 5.2 Ученик
1. Предложений в план от ученика нет (ни модели, ни API, ни UI). Есть только «Предложить улучшение» продукта → админ-журнал.
2. Тесты: не по расписанию, не по направлению (заголовок жёстко «Курс теории гитары»), в единый список заданий не попадают, теория есть у 5 из 25.
3. `/dashboard` и `/learning` показывают одно и то же; офлайн-ДЗ показывается в 4 местах; план — в 3 (в месячном отчёте — старый legacy-план текущего месяца, независимо от выбранного).
4. Legacy-офлайн-ДЗ из CRM только для чтения, без срока в карточке; «Из прошлых уроков» смешивается с текущими.
5. ДЗ курса: сдача только текстом или ссылкой, файлов нет; у ДЗ v2 файлы есть (5 шт., до 500 МБ видео).
6. Магазин — заглушка; модалка обмена и `redeemReward` — мёртвый код.
7. Главная: ≥ 5 запросов к CRM, молчаливые `catch(() => null)` — при падении CRM часть блоков просто исчезает.
8. Достижения в V2 = только рубежи серии; 14 старых достижений не работают, но каталог и экран остались.
9. Points после cutover копятся только с тем плана: ученик без опубликованного плана не растёт в LEVEL, что бы ни делал.

### 5.3 Родитель
1. Баланс = только `Student.accountBalance`; долг по абонементу (`remainingAmountKzt`) не учитывается → «оплачено полностью» при долге по абонементу.
2. Нет истории посещений и пропусков, хотя уведомление о пропуске пишет «подробности в семейном кабинете»; нет абонемента (остаток, срок), хотя balance-alert пишет «информация об абонементе доступна в кабинете».
3. Уведомления родителю игнорируют `ParentVisibilityPolicy` (balance-alert уходит при `showBalance=false`).
4. Весь экран падает при `CRM_NOT_LINKED` или недоступной CRM — пропадают даже достижения и план.
5. Диалог с преподавателем появляется только после того, как преподаватель сам открыл почту; начать диалог, написать куратору или админу родитель не может.
6. «Достижения» для родителя = рубежи серии недель (4/8/12…) — непонятная родителю сущность.
7. Два независимых пути заведения родителя (админ платформы и CRM-оформление) не сверяются; CRM не знает родителей, заведённых на платформе; архив ученика не отзывает `ParentStudentLink`.
8. Ссылки из уведомлений `?notice=&event=` страницей не обрабатываются.

### 5.4 Внутренние курсы для не-учеников
1. Оплаты нет нигде: ни цены у `Course`, ни free/paid, ни срока доступа, ни провайдера. README подтверждён кодом.
2. Регистрация: `POST /auth/register` открыт (без подтверждения телефона), но страница `/register` — заглушка «доступ выдаёт школа»; `/trial-lesson` после заявки ведёт на эту заглушку. При регистрации через API аккаунт **автоматически создаётся в CRM** как ученик (`sync-from-app`).
3. Зачисление: любой ученик на любой опубликованный курс без проверок; повторный enroll сбрасывает `completed` в `active`; ручного зачисления админом нет.
4. Контент: видео только embed YouTube/Vimeo/Cloudflare без подписанных ссылок; файлы медиатеки лежат на диске и отдаются `GET /media/:folder/:file` **без авторизации**; загрузка base64 ≤ 20 МБ, без антивируса.
5. Для внешнего ученика сломаны `/school-lessons`, `/monthly-plan` (`CRM_NOT_LINKED`), `/learning` показывает «не всё загрузилось», сообщения пусты, онлайн-урок невозможен.

7. Курсов на проде 0 (seed без курсов, `prepare-production.ts` удаляет все курсы); курс теории существует только как 25 тестов в коде; `course.json` в репозитории нет.

## 6. Дыры вне четырёх задач (то, о чём не спрашивали)

**Деньги и доверие (P0)**
- Reopen урока в CRM откатывает списание, награды на платформе остаются; коррекции Points нет ни у кого (ECON-037…041 не реализованы).
- Points за тему группе без снимка (5.1.7).
- Coins: начисление читает баланс без `FOR UPDATE`, параллельное списание в магазине может потерять операцию; ленивый вход в эпоху перезаписывает кошелёк на 200 поверх начисленного; кошелёк с `economicEpochId = NULL` валит финализацию недели для всех (если он в топ-3), job повторяет ошибку каждый час.
- Weekly job финализирует только прошлую неделю; простой > 7 дней = потерянные снимки и призы.
- Legacy-уроки (до 1.09), одобренные после cutover, падают в финализации (`WEEKLY_XP_POLICY_REQUIRED`), `rewardsAppliedAt` не ставится.

**Интеграция и безопасность (P0/P1)**
- Один общий секрет на обе стороны, самообъявляемый `X-Integration-System`.
- Медиатека курсов публична без авторизации.
- Пароль: платформа → CRM не передаёт; смена в CRM при упавшем синке расходится молча (`reset-password`, `change-password` игнорируют результат).
- `GET /reconciliation/snapshot`, который вызывает сверка CRM, на платформе не существует.
- Колбэк approve без `crmStudentIds` → уведомления не доходят.
- В снимке лиги для учеников с 0 XP пишется полное имя, не «Имя Ф.».

**Код и доки (P2)**
- Legacy-контур целиком остался: старая навигация, legacy-планы, ручные Points/Coins онлайн-уроков, старые ранги, 14 достижений, `redeemReward`, `CommercialShop`, флаг `studentWorkspaceV2` нигде не читается.
- `docs/student-gamification-contract.md` (22.08) противоречит коду в 6 местах; `08-dev-05` — в 7.
- `teacher-workspace-product-policy.md` обещает таймер, «Требуют внимания» с настраиваемыми порогами, напоминания через 30 мин — пороги захардкожены, таймер есть, динамика за период отсутствует.
- Android: TWA 1.0.2, APK раздаётся с сайта, в Play нет; два разных домена для TWA и ссылки на пробный урок.
