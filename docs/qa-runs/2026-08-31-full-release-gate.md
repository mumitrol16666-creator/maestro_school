## Зависимости

- web production dependencies: **0 уязвимостей**;
- Learning backend: npm сообщает одну цепочку из трёх high-записей
  `prisma -> @prisma/config -> deepmerge-ts`;
- CRM backend: та же цепочка из трёх high-записей.

Advisory относится к исчерпанию стека при объединении рекурсивного графа в
`deepmerge-ts`. В проекте Prisma config получает доверенную локальную
конфигурацию и не обрабатывает пользовательский HTTP-ввод, поэтому прямой
удалённый путь эксплуатации не обнаружен. Обновление Prisma/deepmerge нужно
провести отдельной задачей с повторением DB-регрессии; слепой `npm audit fix`
перед релизом не применять.

## Оставшиеся production gates

До фактического deploy обязательны:

1. Запустить оба `release:preflight` с реальными production env.
2. Подтвердить S3-совместимое приватное хранилище и ClamAV для вложений.
3. Сделать backup и rehearsal восстановления production DB.
4. Выполнить dry-run миграций и economy cutover, затем применить миграции.
5. Собрать immutable images с `RELEASE_SHA` и `RELEASE_BUILT_AT`.
6. После deploy выполнить только read-only production smoke и проверить
   desktop, iPhone/PWA, CRM sync, уведомления и загрузку вложений.
7. Сохранить rollback-образы и не удалять legacy-таблицы в первом релизе.
