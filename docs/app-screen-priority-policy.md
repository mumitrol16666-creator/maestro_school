# Maestro: приоритеты экранов и навигация приложения

Статус: обязательная продуктовая политика  
Дата фиксации: 26 июля 2026 года  
Область: ученическое, преподавательское и административное приложение

## 1. Проблема

Приложение растёт быстрее, чем его информационная архитектура. Новые функции
добавлялись отдельными маршрутами и пунктами меню:

- у ученика сейчас девять пунктов бокового меню и шесть действий в мобильной
  нижней панели;
- у преподавателя отдельно показаны офлайн- и онлайн-уроки;
- у администратора доступно более десяти самостоятельных разделов;
- часть функций дублируется между главной, уведомлениями и отдельными страницами;
- важные ежедневные действия конкурируют с редко используемыми настройками.

Количество технических маршрутов может расти. Количество решений, которые
пользователь видит на одном уровне, должно быть ограничено.

## 2. Основное правило

Для каждой роли допускается не более пяти разделов первого уровня.

Новая функция не получает отдельную кнопку в нижнем меню автоматически. Сначала
она должна быть размещена внутри существующего пользовательского сценария.

```text
роль → 4–5 основных разделов → вкладки сценария → карточка объекта → действие
```

Ограничения:

- нижняя мобильная навигация: максимум 5 пунктов;
- постоянное боковое меню роли: максимум 7 пунктов;
- вкладки внутри раздела: максимум 4 одновременно;
- основное действие экрана: одно;
- второстепенные действия: меню или нижняя зона карточки;
- сложная форма открывается страницей, а не многоэтажным модальным окном.

## 3. Приоритет функций

### P0 — ежедневная работа

Функция нужна большинству пользователей каждый рабочий день или блокирует
обучение и деньги.

Примеры:

- сегодняшний урок;
- посещаемость и отчёт;
- сообщение или задача;
- подтверждение урока;
- расписание;
- быстрый обзор управляющего.

P0 может находиться в главной навигации.

### P1 — регулярная учебная и операционная работа

Используется несколько раз в неделю:

- ученики и группы;
- месячные планы;
- курсы и тесты;
- проверка ДЗ;
- внутренний магазин и склад CRM;
- заказы магазина.

P1 находится внутри одного из основных разделов и не обязан получать отдельный
пункт нижнего меню.

### P2 — развитие и удержание

- достижения;
- ранги;
- Maestro Coins;
- витрина наград;
- новости;
- расширенная статистика.

P2 не должна вытеснять P0 из первого экрана.

### P3 — редкое администрирование

- роли и доступы;
- справочники;
- интеграционные настройки;
- архивы;
- технические журналы;
- массовые операции.

P3 доступна через настройки или CRM и не показывается в основной мобильной
навигации.

## 4. Целевая навигация ученика

Нижняя панель содержит пять пунктов:

| Раздел | Содержимое | Приоритет |
|---|---|---|
| Главная | следующий урок, задачи, уведомления, новости | P0 |
| Обучение | курсы, тесты, прогресс, домашние задания | P0/P1 |
| Расписание | офлайн- и онлайн-уроки | P0 |
| Магазин | товары, корзина, заказы, позже Coins | P1/P2 |
| Сообщения | обращения и ответы преподавателя | P0 |

Профиль и настройки открываются через аватар в шапке. Отдельная кнопка «Профиль»
в нижней панели не нужна.

### Перенос существующих маршрутов

| Сейчас | Целевое место |
|---|---|
| `/courses` | Обучение → Курсы |
| `/tests` | Обучение → Тесты |
| `/progress` | Обучение → Прогресс |
| `/school-lessons` | Расписание → В школе |
| `/online-lessons` | Расписание → Онлайн |
| `/rewards` | Магазин → Привилегии или кошелёк |
| `/board` | Главная → Новости |
| `/settings` | Аватар → Профиль |
| `/messages` | Сообщения |

Существующие URL можно сохранить для совместимости и уведомлений. Они перестают
быть независимыми пунктами первого уровня.

## 5. Целевая навигация преподавателя

Нижняя панель содержит четыре основных раздела:

| Раздел | Содержимое | Приоритет |
|---|---|---|
| Главная | уроки сегодня, незакрытые отчёты, задачи | P0 |
| Уроки | офлайн и онлайн как две вкладки | P0 |
| Ученики | мои ученики, мои группы, планы, материалы | P0/P1 |
| Сообщения | обращения учеников и уведомления | P0 |

Профиль и настройки находятся в шапке.

Офлайн- и онлайн-уроки не должны занимать две позиции нижнего меню. Это один
раздел `Уроки` с переключателем режима.

Карточка ученика объединяет:

- учебный контекст;
- месячный план;
- динамику;
- материалы;
- историю уроков;
- сообщение ученику.

Для каждой из этих функций не создаётся отдельное окно первого уровня.

## 6. Целевая навигация администратора

Мобильное приложение администратора предназначено для быстрого контроля, а не
для копирования всей CRM.

| Раздел | Содержимое | Приоритет |
|---|---|---|
| Обзор | сводка дня, риски, ожидаемые оплаты, задачи | P0 |
| Уроки | офлайн, онлайн, подтверждения, ДЗ, вопросы | P0 |
| Люди | ученики, преподаватели, пользователи | P0/P1 |
| Коммуникации | задачи, сообщения, уведомления | P0 |
| Ещё | контент, магазин, настройки и редкие операции | P1–P3 |

Полный склад, касса, зарплата, роли и технические журналы остаются в CRM.
Приложение может показывать краткую сводку и вести к нужному действию, но не
создаёт мобильные копии каждого административного экрана.

### Группировка существующих административных маршрутов

| Группа | Маршруты |
|---|---|
| Уроки | offline-lessons, online-lessons, homework-review, lesson-questions |
| Люди | students, my-students, users |
| Обучение | directions, courses, tests, media |
| Коммуникации | messages, news, уведомления |
| Управление | rewards, settings и редкие справочники |

## 7. Магазин в приложении

Полная складская логика принадлежит CRM. В ученическом приложении магазин
появляется только после готовности интеграционного API.

Минимальный набор экранов:

1. каталог с поиском и категориями;
2. карточка товара;
3. корзина;
4. оформление резерва или заказа;
5. история заказов.

Эти пять состояний находятся внутри одного раздела `Магазин`, а не добавляются
в главное меню отдельными окнами.

Maestro Coins добавляются внутрь этого раздела как кошелёк и способ получить
скидку. Отдельный первый уровень `Награды` после запуска магазина не нужен.

## 8. Уведомления и точки входа

Уведомление должно вести прямо к объекту:

- урок → карточка урока;
- сообщение → конкретная переписка;
- заказ → карточка заказа;
- тест → попытка теста;
- задача → карточка задачи.

Счётчик показывается на разделе, внутри которого находится действие. Нельзя
дублировать один непрочитанный объект на нескольких пунктах меню.

Входящий попап используется только для критичных событий:

- урок требует действия сегодня;
- администратор вернул отчёт;
- пришёл ответ на обращение;
- заказ готов.

Остальные события остаются в центре уведомлений.

## 9. Правило создания нового экрана

Перед добавлением маршрута команда отвечает на вопросы:

1. Какая роль использует экран?
2. Какую одну задачу он закрывает?
3. Как часто задача выполняется?
4. Почему она не помещается в существующий раздел?
5. Что будет убрано или объединено при добавлении нового пункта меню?
6. Нужен ли отдельный URL для уведомления или достаточно состояния карточки?
7. Как экран работает на ширине 320–430 px без горизонтального движения?

Если на четвёртый вопрос нет убедительного ответа, новая функция добавляется
вкладкой, блоком карточки или действием существующего экрана.

## 10. Мобильные требования

- горизонтальная прокрутка страницы запрещена;
- таблицы преобразуются в списки или компактные строки;
- основная кнопка доступна большим пальцем;
- нижняя панель не перекрывает контент;
- поля и кнопки имеют высоту не менее 44 px;
- длинное имя переносится или сокращается без изменения ширины карточки;
- технические идентификаторы не показываются пользователю;
- модальное окно не содержит многошаговую рабочую форму;
- экран проверяется на 320, 375, 430 и 768 px.

## 11. Метрики приоритета

Для каждого раздела собираются:

- недельная доля пользователей роли;
- количество открытий;
- количество завершённых действий;
- среднее время до результата;
- доля выходов без действия;
- количество непрочитанных объектов;
- ошибки и повторные отправки.

Кандидат на удаление из первого уровня:

- используется менее чем 20% пользователей роли за неделю;
- не имеет срочных непрочитанных событий;
- не является обязательным шагом P0;
- может быть открыт из родительского раздела.

## 12. План перехода

### Этап 1. Безопасная перегруппировка

- сохранить существующие URL;
- сократить мобильную панель ученика до пяти пунктов;
- объединить уроки преподавателя;
- скрыть профиль и новости из первого уровня;
- добавить роль-зависимые группы в меню администратора.

### Этап 2. Объединённые разделы

- создать контейнер `Обучение`;
- создать контейнер `Расписание`;
- создать контейнер `Уроки` преподавателя;
- перенести счётчики на родительские разделы.

### Этап 3. Магазин

- добавить один пункт `Магазин`;
- встроить каталог, корзину и заказы;
- перенести привилегии и будущий кошелёк Coins внутрь магазина.

### Этап 4. Очистка

- убрать дублирующие входы;
- удалить неиспользуемые пункты после анализа метрик;
- оставить redirect для старых ссылок;
- проверить все роли и мобильные разрешения.

## 13. Критерии приёмки

1. У каждой роли не более пяти мобильных пунктов первого уровня.
2. Главная показывает только задачи текущего дня и ближайшие риски.
3. Ученик находит курс, тест и прогресс внутри одного раздела.
4. Офлайн- и онлайн-уроки не дублируются в нижней панели.
5. Профиль доступен через аватар.
6. Новый магазин занимает один раздел.
7. Старые ссылки из уведомлений продолжают работать.
8. На ширине 320 px отсутствует горизонтальная прокрутка.
9. Непрочитанный объект имеет один понятный счётчик и одну точку входа.
10. Редкие административные операции не конкурируют с ежедневной работой.
